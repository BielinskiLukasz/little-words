<task type="auto">
  <name>Task 2: Fix add-entry sheet stays open after no-meaning save (G-03-popup)</name>
  <files>src/db/services/wordEntry.service.ts, src/features/add-entry/hooks/useAddEntry.ts</files>
  <action>
    Two changes are required, in dependency order:

    CHANGE A — wordEntry.service.ts (remove empty-meaning guard):

    The function addWordEntry currently contains this block after filtering meanings:

      const validMeanings = data.meanings.filter(m => m.text.trim().length > 0)

      if (validMeanings.length === 0) {
        throw new Error('At least one non-empty meaning is required')
      }

    Remove the entire if-block (lines 51-53). Keep the filter on the line above; the
    resulting validMeanings array may be empty. The rest of the function already handles an
    empty validMeanings: the for-of loop over validMeanings does nothing, meaningIds stays
    [], and the function returns { wordFormId, meaningIds: [] }. This is the correct
    behavior — a word form saved with no meanings is valid.

    Do not remove the earlier guard ("At least one meaning is required" when
    data.meanings.length === 0) — that guard protects callers that pass no meanings array
    at all, which is a programming error, not a user action.

    CHANGE B — useAddEntry.ts (move cleanup to finally):

    In handleSave(), the current try/catch/finally is:

      try {
        ...
        await addWordEntry({ wordForm, meanings })
        setIosInstallPromptSeen(true)
        setAddWordSheetOpen(false)   // <-- moves to finally
        reset()                      // <-- moves to finally
      } catch (err) {
        setError(err instanceof Error ? err.message : 'Unknown error')
      } finally {
        setIsLoading(false)
      }

    Move setAddWordSheetOpen(false) and reset() from the try block to the finally block,
    after setIsLoading(false). The corrected finally block must be:

      } finally {
        setIsLoading(false)
        setAddWordSheetOpen(false)
        reset()
      }

    Leave setIosInstallPromptSeen(true) inside the try block (it should fire only on a
    successful save). The catch block is unchanged — it only sets the error state.

    After this change: when addWordEntry resolves (word form saved, with or without
    meanings), the sheet closes and the form resets. When addWordEntry rejects (e.g. empty
    wordForm field), the error is shown AND the sheet still closes. This matches the UAT
    truth: "sheet closes after a save attempt regardless of whether a meaning was entered".
  </action>
  <verify>
    <automated>npx vitest run src/features/add-entry 2>&amp;1 | tail -20</automated>
  </verify>
  <done>
    Build and tests pass. In wordEntry.service.ts, the "At least one non-empty meaning is
    required" throw is absent. In useAddEntry.ts, setAddWordSheetOpen(false) and reset()
    appear in the finally block, not the try block. Saving a word form with empty meaning
    rows completes without an error and would trigger the finally cleanup path.
  </done>
