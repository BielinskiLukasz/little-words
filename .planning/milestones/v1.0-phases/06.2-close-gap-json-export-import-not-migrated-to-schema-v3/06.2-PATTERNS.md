### `src/features/settings/services/dataManagement.ts` (service, CRUD validation + transform)

**Analog:** Same file — `isValidChildProfile` and `isValidMeaning` functions show the strict-typing validator pattern to apply to the new `isValidWordFormMeaning`.

**Strict-typing validator pattern** (lines 31-40 and 48-57):

```typescript
// isValidChildProfile example (lines 31-40)
function isValidChildProfile(item: unknown): boolean {
  if (typeof item !== 'object' || item === null) return false
  const p = item as Record<string, unknown>
  return (
    typeof p.name === 'string' &&
    typeof p.birthDate === 'string' &&
    Array.isArray(p.languages) &&
    typeof p.createdAt === 'string'
  )
}

// isValidMeaning example (lines 48-57)
function isValidMeaning(item: unknown): boolean {
  if (typeof item !== 'object' || item === null) return false
  const m = item as Record<string, unknown>
  return (
    typeof m.text === 'string' &&
    Array.isArray(m.categories) &&
    typeof m.isActive === 'boolean' &&
    typeof m.firstUseDate === 'string' &&
    typeof m.lastUseDate === 'string'
  )
}
```

**Key pattern characteristics:**
- Type guard: null check first
- Cast to `Record<string, unknown>` for safe property access
- Individual `typeof` or `Array.isArray()` checks for each field
- No loose/presence-only checking — all fields required with correct types
- Boolean fields checked with `typeof m.isActive === 'boolean'`
- String date fields checked with `typeof ... === 'string'`

**Application to new `isValidWordFormMeaning`:** 
The new implementation must follow the same pattern for v3 fields: check `firstObservationDate: string`, `lastUsedDate: string`, `isActive: boolean` (plus existing `wordFormId: number` and `meaningId: number`).
