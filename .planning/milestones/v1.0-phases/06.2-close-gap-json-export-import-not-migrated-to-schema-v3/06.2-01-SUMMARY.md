# Phase 06.2 Plan 01: JSON Export/Import Validated Against Schema v3 Summary

Extracted a single `BACKUP_SCHEMA_VERSION = 3` constant used by all three former hardcoded-`2` call sites in `dataManagement.ts` (`buildBackupData`, `validateBackupData`'s own internal check, and `importData`'s version check), and tightened `isValidWordFormMeaning` to require the three v3 per-pair fields (`firstObservationDate`, `lastUsedDate`, `isActive`) — closing milestone v1.0 audit blocker 2 so restored backups no longer silently corrupt the per-pair rollup fields Phase 6 introduced.

## Accomplishments
- `BACKUP_SCHEMA_VERSION = 3` is now the single source of truth for `buildBackupData`, `validateBackupData`, and `importData`'s version check — no more independently-hardcoded `2` literals, including the internal `validateBackupData` check that CONTEXT.md flagged as a load-bearing third site not called out by line number in the canonical refs.
- `isValidWordFormMeaning` now enforces `firstObservationDate: string`, `lastUsedDate: string`, and `isActive: boolean` alongside the existing `wordFormId`/`meaningId` number checks, mirroring the exact strict-typing style already used by `isValidChildProfile`/`isValidMeaning`.
