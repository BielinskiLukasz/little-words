# Phase 06.3 Plan 01: Import Validation Footgun Fix Summary

**validateBackupData now rejects any backup whose childProfile array isn't exactly length 1, and importData surfaces this as a distinct `invalid-child-profile-count` error (not the generic `corrupt`) with its own parent-facing message in both locales, checked before any table is cleared.**

## Accomplishments
- Closed the v1.0 milestone audit's data-loss/lockout footgun: a hand-edited or corrupted backup with an empty or multi-profile `childProfile` array is now rejected before `db.transaction` clears existing tables, so a parent can never end up with zero profile rows and orphaned `wordForms`/`meanings`/`wordFormMeanings`.
- `importData` now distinguishes three failure modes with distinct `Error` messages (`wrong-schema-version`, `invalid-child-profile-count`, `corrupt`), each mapped to its own plain-language i18n string in `DataSection.tsx`.
- Added 5 new regression tests (3 at the `validateBackupData` layer, 2 at the `importData` layer) plus updated 4 pre-existing test fixtures whose `childProfile: []` shape is no longer a valid backup under the new invariant.
