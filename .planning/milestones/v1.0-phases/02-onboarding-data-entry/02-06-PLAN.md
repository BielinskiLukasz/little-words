## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06-01 | Information Disclosure | AddEntrySheet error display | low | accept | Error messages come from Dexie and application code only; no user data is reflected in error strings; role=alert is accessible but not a leak vector |
| T-02-06-02 | Tampering | wordEntry.service existingMeaningId branch | medium | mitigate | Service must not blindly trust existingMeaningId — if the id does not exist in db.meanings, linkMeaningToWordForm will create a junction row with a dangling meaningId. Mitigation: the existing linkMeaningToWordForm idempotency logic handles this silently; a dangling id produces a harmless orphan junction row, not a data corruption. A strict mitigation (db.meanings.get(existingMeaningId) check) is deferred as a non-blocker improvement. |
| T-02-06-03 | Denial of Service | db.transaction scope | low | accept | The transaction holds locks on three tables; all operations are O(n) where n is the number of meaning rows per entry (typically 1-5). Lock contention is not a concern in a single-user offline app. |
</threat_model>
