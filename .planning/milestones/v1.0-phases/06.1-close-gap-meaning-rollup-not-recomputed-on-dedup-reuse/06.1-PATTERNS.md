export async function updatePairFields(
  pairId: number,
  fields: Partial<Pick<WordFormMeaning, 'firstObservationDate' | 'lastUsedDate' | 'isActive'>>
): Promise<void> {
  await db.transaction('rw', [db.wordFormMeanings, db.meanings], async () => {
    await db.wordFormMeanings.update(pairId, fields)
    const pair = await db.wordFormMeanings.get(pairId)
    if (pair) {
      await aggregateMeaningFromPairs(pair.meaningId)
    }
  })
}
```

**Why this pattern applies:**
- `linkMeaningToWordForm` must call `aggregateMeaningFromPairs` to recompute the parent meaning's `isActive`, `firstUseDate`, and `lastUseDate` fields (D-01)
- The transaction wraps both `db.wordFormMeanings` (write the pair) and `db.meanings` (aggregate the parent) to keep them in sync (D-02)
- The early-return path (when pair already exists, lines 25-27) does NOT call `aggregateMeaningFromPairs` because nothing changed (D-02)

**Aggregation function reference** (`src/db/services/meaning.service.ts`, lines 18-29):

export async function aggregateMeaningFromPairs(meaningId: number): Promise<void> {
  const pairs = await db.wordFormMeanings.where('meaningId').equals(meaningId).toArray()
  if (pairs.length === 0) return

  const isActive = pairs.some(p => p.isActive)
  const firstUseDateMs = Math.min(...pairs.map(p => new Date(p.firstObservationDate).getTime()))
  const lastUseDateMs = Math.max(...pairs.map(p => new Date(p.lastUsedDate).getTime()))
  const firstUseDate = new Date(firstUseDateMs).toISOString().slice(0, 10)
  const lastUseDate = new Date(lastUseDateMs).toISOString().slice(0, 10)

  await db.meanings.update(meaningId, { isActive, firstUseDate, lastUseDate })
}
```
(This function already exists and requires no changes; just needs to be called from the new site.)

## Key Insights

1. **Transaction safety (D-02):** The fix wraps both the junction table write and the parent Meaning aggregation in a single transaction, ensuring they stay in sync. This matches the existing pattern in `updatePairFields` and `deleteWordForm`.

2. **Early-return optimization (D-02):** When `linkMeaningToWordForm` detects an existing pair (lines 25-27), it returns without calling `aggregateMeaningFromPairs` because no pair data changed, so there is nothing to re-aggregate. This keeps the fix strictly scoped to the reported gap.

3. **Integration entry point:** The dedup bug surfaces in `addWordEntry`'s dedup branch (wordEntry.service.ts:58-70), where an existing Meaning is linked via `linkMeaningToWordForm` but the parent Meaning is not re-aggregated. The fix at the service layer ensures both the new-meaning and dedup branches work correctly.

4. **Test coverage (D-03):**
   - Unit test: Assert that `linkMeaningToWordForm` triggers aggregation (following `updatePairFields` test pattern)
   - Integration test: Assert that the dedup scenario in `addWordEntry` correctly refreshes the parent Meaning's fields (following existing integration test pattern)
