<objective>
Close milestone v1.0 audit blocker 1: `linkMeaningToWordForm` (`src/db/services/wordFormMeaning.service.ts`) creates a junction row but never re-aggregates the parent `Meaning`'s `isActive`/`firstUseDate`/`lastUseDate` rollup. This is silently wrong today for the add-entry autocomplete dedup path — reusing an existing (possibly inactive) meaning on a new word form leaves the Dashboard's Active Meanings count and the Doctor Report reading stale data (DASH-01, DASH-02, DASH-03, REPORT-01).

This is a single-call-site fix with no UI/API/DB layers to slice through — the whole phase scope is one service-layer function plus its test coverage. Per tracer-first guidance, this plan's one TDD feature IS the tracer: it is the thinnest possible change that closes the gap end-to-end (junction write -> aggregate recompute -> Dashboard/Report read correct data), proven by a real vitest run, not a horizontal layer.

Purpose: Restore the invariant established in Phase 6 (D-02): "Meaning.isActive aggregation must be recalculated on every WordFormMeaning write (create, update, delete)." `linkMeaningToWordForm` was the one exception; this plan removes it.
Output: `linkMeaningToWordForm` re-aggregates its parent Meaning on every new-pair insert (never on the idempotent no-op path), with a unit test proving the aggregation call and an integration test reproducing the exact audit scenario end-to-end through `addWordEntry`.
</objective>
