<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User file system → importData | User-selected JSON file parsed and loaded into IndexedDB; primary attack surface |
| IndexedDB → Blob download | All user data serialized to JSON/CSV and offered as a download; user-initiated only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-04 | Tampering | importData — JSON file overwrites all IndexedDB data | high | mitigate | validateBackupData runs BEFORE any clear/bulkAdd; schemaVersion must equal 2; all four array fields must exist; corrupt or mismatched files are rejected with an error dialog and existing data is preserved (D-17) |
| T-04-05 | Elevation of Privilege | importData — malicious JSON injecting unexpected fields | low | accept | Dexie bulkAdd ignores unknown fields not in the schema index; IndexedDB is isolated to origin; no XSS vector from stored values that are only read and displayed |
| T-04-06 | Information Disclosure | exportData/exportMeaningsCSV — all PII exported to user's file system | low | accept | Export is always user-initiated via explicit button tap; no auto-export; file goes to user's own download directory; offline-only app has no server to leak data to |
| T-04-07 | Denial of Service | importData clears all tables before bulkAdd — data loss if bulkAdd fails mid-transaction | medium | mitigate | All clear + bulkAdd operations run inside a single Dexie transaction ('rw'); if bulkAdd throws, the transaction rolls back automatically and existing data is restored |
| T-04-SC | Tampering | npm package installs (sonner via shadcn already installed in 04-01) | high | mitigate | No new package installs in this plan; sonner installed in 04-01 plan wave 1 |
</threat_model>
