# Phase 06.3 Plan 04: Widen importData childProfile guard to all invalid shapes Summary

**importData's specific-error pre-check now fires for missing/null/non-array childProfile, not only wrong-length arrays — closing code review finding WR-01, the last gap from 06.3-VERIFICATION.md**

## Performance

- **Duration:** ~12 min
- **Started:** 2026-09-18T10:02:00Z (approx.)
- **Completed:** 2026-09-18T10:14:41Z
- **Tasks:** 1
- **Files modified:** 2

## Accomplishments
- `importData`'s `childProfile` pre-check widened from `Array.isArray(...) && length !== 1` (which skipped missing/null/non-array shapes entirely) to `!Array.isArray(childProfile) || childProfile.length !== 1`, so every invalid shape throws `Error('invalid-child-profile-count')` before `db.transaction` runs
- 3 new importData-level regression tests: missing `childProfile` key, `childProfile: null`, and `childProfile: 'not-an-array'` — each asserts the specific error message and `testDb.childProfile.count() === 0` afterward (zero-write guarantee preserved)
- 2 new validateBackupData-level regression tests confirming that function already returned `false` correctly for `null` and non-array `childProfile` — no code change needed there, only coverage
- All 39 tests in `dataManagement.test.ts` pass (34 pre-existing + 5 new); full suite is 188/188; `npm run build` and `npm run lint` both succeed
